# manifest-kinds

The manifest-kinds family covers design §4.2's `folder` and `json` kinds. A folder kind is a marker file that defines one doc with its merged files, and a json kind is an array whose entries are docs. Its prefix is `MANK`, and its topics are FOLDER, JSON, TITLE, MERGE, ROOTS and CITE. TITLE is the one-liner rule that every kind shares (design §4.2 `title`). MERGE is a folder's `merge` file that cannot be read, and ROOTS is a manifest root that is a symlink leading outside the repo. CITE is where a folder or json doc's relative citations resolve from: the folder that holds its marker, or the folder of its JSON file, then the root (design §2.3). MERGE and ROOTS are unix only, since they use permissions and a symlink. Its cases are built: each one is a real manifest in `.memex/collections/` that the loader of the `manifest` family reads, so `show` observes the docs and warnings. `json.rs` keeps six unit tests of its reader on temporary fixture trees, and `folder.rs` has none. The rulings that these cases pin are written into their claims. Two points remain pending a ruling: the warning that a marker or data file that does not parse prints, which MANK-FOLDER-09 and MANK-JSON-07 pin, since the design names warnings for manifests only; and a folder whose marker lacks the field named by `id` gives no doc, which MANK-FOLDER-06 pins.
