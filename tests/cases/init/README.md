# init

The init family covers design §3.5b and §6.1: what `memex init` does to a folder, and that a second run changes nothing. It covers the `.memex/` files and their never-overwrite rule, the AGENTS.md block with its append, replace, kept and damaged-marker paths, the markers and the CLAUDE.md import outside fenced code (FENCE), a symlinked AGENTS.md or CLAUDE.md that is never written through (LINK, unix only), the target folder (the toplevel, found by listing with or without git: INIT-NOGIT-01; outside a repo, the nearest folder above with `.memex/`, else the cwd: NEST), a hand-pasted snippet without markers that init leaves alone (PASTE), the self-install and its PATH hint, the npx shim that does not count as an install (INIT-PATH-03 on unix, INIT-PATH-05 on Windows), the Windows `memex.cmd` that does count (INIT-PATH-04), the exact bytes of the new config.json (INIT-FRESH-02), the atlas that ends the report, the re-run, and the exit 3 of an I/O failure (IO, unix only). Its prefix is `INIT`.

Every case that is not about the install sets `memex_on_path` to true, so the binary is not copied into the sandbox home and the golden is the same on every OS. The install cases, INSTALL and the install parts of PATH (PATH-03 and PATH-05 included), are the only ones that run the copy. PATH-04 and PATH-05 set their own PATH, which replaces the one that `memex_on_path` would prepend, so they leave `memex_on_path` unset. The LINK cases make their symlink with a patch that `git apply` runs in the sandbox, as LOG-PRUNE-14 does, and they run in a folder that is not a git repo: a snapshot of `repo` then lists the link as `(symlink)`, since a snapshot of the link path itself follows it. INSTALL-02 is the Windows twin of INSTALL-01 and has no golden made on unix: its expect.txt is derived by hand from INSTALL-01 (the install path under `home/AppData/Local/Programs/memex`, the file `memex.exe`, and the blank row as `| `), and the first Windows run confirms it.

INIT-PATH-04 and INIT-PATH-05 are Windows cases too, with the same hand-derived goldens and the same wait for a Windows run. Their PATH is a relative folder, `bin` or `node_modules\.bin`, read from the run's folder `repo/`, and the fixture gives that folder a `memex.cmd`. The setup cannot use `git apply` for it, because the case's PATH may leave git off the search path on Windows, so the fixture carries the file. INIT-PATH-05's golden is the INSTALL-02 golden, and INIT-PATH-04's is the PATH-02 golden with the install folder missing.

The CASES.md claim index holds each case's claim and its design section. Where design §3.5b is silent, the claim says so and pins the choice.
