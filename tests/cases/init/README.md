# init

The init family covers design §3.5b and §6.1: what `memex init` does to a folder, and that a second run changes nothing. It covers the `.memex/` files and their never-overwrite rule, the AGENTS.md block with its append, replace, kept and damaged-marker paths, the markers and the CLAUDE.md import outside fenced code (FENCE), a symlinked AGENTS.md or CLAUDE.md that is never written through (LINK, unix only), the target folder (the git toplevel, else the cwd), the self-install and its PATH hint, the npx shim that does not count as an install (PATH-03, unix only), the atlas that ends the report, the re-run, and the exit 3 of an I/O failure (IO, unix only). Its prefix is `INIT`.

Every case that is not about the install sets `memex_on_path` to true, so the binary is not copied into the sandbox home and the golden is the same on every OS. The install cases, INSTALL and the install parts of PATH (PATH-03 included), are the only ones that run the copy. The LINK cases make their symlink with a patch that `git apply` runs in the sandbox, as LOG-PRUNE-14 does, and they run in a folder that is not a git repo: a snapshot of `repo` then lists the link as `(symlink)`, since a snapshot of the link path itself follows it. INSTALL-02 is the Windows twin of INSTALL-01 and has no golden made on unix: its expect.txt is derived by hand from INSTALL-01 (the install path under `home/AppData/Local/Programs/memex`, the file `memex.exe`, and the blank row as `| `), and the first Windows run confirms it.

The CASES.md claim index holds each case's claim and its design section. Where design §3.5b is silent, the claim says so and pins the choice.
