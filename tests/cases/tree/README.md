# tree

The tree family covers design §3.5e and §3.6, the listing of `memex tree`. Its prefix is `TREE`. Each case folder holds a small repo as its fixture: READMEs, files with and without headers, a folder with no README, folders of data alone, and, where a case needs them, Markdown files, empty and binary files, and paths the walk skips. DEFAULT, DEPTH and SCOPE pin the listing at the root, to a depth and for a path, a file or a path that names nothing; USAGE and HELP pin the usage errors and the help text. NOHDR pins the `(no README)` placeholder and the data-only folder that gets none, FILE the line of each kind of file, COUNT the counts of a folder, GAP the gap lines, LIMIT the cut list and its heading, ORDER the depth-first order, JSON the document and SKIP the paths the walk leaves out, OUTSIDE a path outside the root (a cheap `not found` that walks no other root) and READ a README that cannot be read and SYMLINK a path through a link inside the root, which names nothing.

Where design §3.5e is silent, these cases pin the choice: the scope line of the root names `.`; a count of one is singular on the first line as on a folder line (`1 file`); an empty path is a usage error, as it is for `audit`; a path that names two entries is a fatal `ambiguous` with exit 1; a file path lists the file at depth 1, whatever its name.
