# audit

The audit family covers design §3.5d and §3.6, the report of `memex audit`. Its prefix is `AUD`. The report is about the root, or about the paths and globs it is given. Each case folder holds a small intent layer as its fixture: a root README, folders with and without READMEs, files with and without headers and, where a case needs them, a collection with a duplicate id, unresolved references and a log entry. SCOPE and GLOB pin which files and folders a scope holds, and OUTSIDE that a path outside the root is a cheap `not found` that walks no other root. HEADERS, READMES, ONELINERS, CITES, IDS and ROOTS pin one finding kind each. LIMIT pins the default of 20 and `--limit`, and JSON the document. EMPTY pins the clean report, and EXIT the exit codes: a finding exits 0, a path that names nothing exits 1, and a usage error exits 2. The `length` and `thin` kinds are pinned under LENGTH and THIN, and the refiner's findings under REFINE.
