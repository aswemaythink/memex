# collection

The collection family covers the frontmatter half of design §2.2 and the collection rules of §4.2: a Markdown file whose frontmatter holds `memex: <name>` is a doc in that collection, a file whose column-0 items open with case ids is an entry index of it, and a README is the graph's, so its `memex:` key is ignored. Its prefix is `COLL`. The FRONT topic covers how the frontmatter is found (a byte order mark, CRLF line ends, a fence that never closes, the 8 KiB limit), NAME the grammar of a collection name, ONE a file that is one doc, ENTRY an entry index, PLAIN a CASES.md without the key, README the key in a README, UNREAD a Markdown file that cannot be read, CITE the citations of collection docs and entries, and INFO the collections line.

Each case folder holds its own fixture repo. Where design §2.2 is silent, these cases pin the choice: a `memex:` line counts only when the whole line lies inside the first 8 KiB (COLL-FRONT-06; a ruling not yet in PLAN §13), and a file longer than 8 KiB is read a second time only when its key is in the head (COLL-FRONT-07). The SHARED topic, for a collection named like the graph or a stream, follows with the next slice.
