# check

The check family covers design §3.5d and §3.6, the report of `memex check`. Its prefix is `CHK`. The report is about the root, or about the paths and globs it is given. Each case folder holds a small intent layer as its fixture: a root README, folders with and without READMEs, files with and without headers and, where a case needs them, a collection with a duplicate id, unresolved references and a log entry. SCOPE and GLOB pin which files and folders a scope holds. HEADERS, READMES, ONELINERS, CITES and IDS pin one finding kind each. LIMIT pins the default of 20 and `--limit`, and JSON the document. EMPTY pins the clean report, and EXIT the exit codes: a finding exits 0, a path that names nothing exits 1, and a usage error exits 2. The `length` and `thin` kinds have no cases here yet; they come with their own line counts.
