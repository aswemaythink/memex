# stress

`stress/` is memex's opt-in stress suite. It runs the built binary at scale, with concurrent writers, on fuzzed input, and against timing budgets. Every test in it is `#[ignore]`, so `cargo test --locked` runs none of them; run the suite with `cargo test --release --test stress -- --ignored`, and narrow it with a name filter such as `scale_`. `main.rs` lists the modules and holds the round-trip smoke test. `support.rs` is the shared code: the binary's path, scratch repositories with a scrubbed environment (`Sandbox`, `cmd`, `run_stdin`), a seeded tree generator (`write_tree`), and timings with the load average (`median_ms`, `min_ms`, `report`). `scale.rs` and `scale_logs.rs` (large trees, log stores, long lines and big files), `concurrency.rs` (parallel writers and prune), `conc_worktrees.rs` (writers in linked worktrees: each entry's `worktree:` field, and `info` from a worktree counting the shared store), `fuzz.rs` (proptest input through the binary), `names.rs` (control-character file names) and `budget.rs` (reference-repo timings, run only when `MEMEX_STRESS_REPO` names a repo) are the families of tests. Timings print the load average; a budget run on a loaded machine says so rather than passing silently. The budgets are medians: `budget.rs` holds the reference-repo budgets (`memex info` 90 ms, `search button` 115 ms, `show packages` 95 ms, `tree` 95 ms and `audit` 150 ms, each the median of nine timed runs), and `scale.rs`'s `scale_100k_files` the 100k-file budgets (info 1300 ms, search 1600 ms, show 1300 ms and audit 2000 ms, each the median of three timed runs). The suite cites no case ids (`Cases: none (stress)`): the conformance cases in [cases](../cases/README.md) pin behaviour, and a stress run measures how long that behaviour takes and whether it holds under load.
