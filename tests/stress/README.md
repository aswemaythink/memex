# stress

`stress/` is memex's opt-in stress suite: the built binary run at scale, with concurrent writers, on fuzzed input, and against timing budgets. Every test in it is `#[ignore]`, so `cargo test --locked` runs none of them; run the suite with `cargo test --release --test stress -- --ignored`, and narrow it with a name filter such as `scale_`. `main.rs` lists the modules and holds the round-trip smoke test. `support.rs` is the shared code: the binary's path, scratch repositories with a scrubbed environment (`Sandbox`, `cmd`, `run_stdin`), a seeded tree generator (`write_tree`), and timings with the load average (`median_ms`, `min_ms`, `report`). `scale.rs` (large trees), `concurrency.rs` (parallel writers and prune), `fuzz.rs` (proptest input through the binary), `names.rs` (control-character file names) and `budget.rs` (reference-repo timings, run only when `MEMEX_STRESS_REPO` names a repo) are the families of tests. Timings print the load average; a budget run on a loaded machine says so rather than passing silently. The suite cites no case ids (`Cases: none (stress)`): the conformance cases in [cases](../cases/README.md) pin behaviour, and a stress run measures how long that behaviour takes and whether it holds under load.
