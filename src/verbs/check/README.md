# check

The parts of `memex check` (design §3.5d). `../check.rs` runs the verb: it resolves the arguments to a scope, finds each kind's findings over it, and hands the summary to `render/check.rs`. `scope.rs` turns the arguments into the files and folders they name: a path is resolved by `resolve/` as `show` resolves one (design §3.1), and a glob (one holding `*`, `?` or `[`) is matched by `collections/globs.rs` with the manifest `include` rules. It also walks the corpus's children into the entries that the counts and the glob matches read, so no file is read. `kinds.rs` holds the kinds, in the order of design §3.5d: `headers`, `readmes`, `one-liners`, `cites` and `ids`. Each is one function over the context, which the `length` and `thin` kinds join later.

Choices where design §3.5d is silent: a path outside the root names nothing, since check reads only the root it runs in; a doc label or bare id is not a path, so it names nothing either; the `headers` kind asks the file system for each candidate's length, and only that, so an empty file is not a finding; a folder that the walk could not list is not judged for a README; an `ids` finding is in scope when any of its docs is; an `ids` detail names each file once, joined by ` · `.
