# check

The parts of `memex check` (design §3.5d). `../check.rs` runs the verb: it resolves the arguments to a scope, finds each kind's findings over it, and hands the summary to `render/check.rs`. `scope.rs` turns the arguments into the files and folders they name: a path is resolved by `resolve/` as `show` resolves one (design §3.1), and a glob (one holding `*`, `?` or `[`) is matched by `collections/globs.rs` with the manifest `include` rules. It also walks the corpus's children into the entries that the counts and the glob matches read, so no file is read. `counts.rs` counts the lines of each in-scope file with a comment family (design §3.5d Lines), for `length` and `thin`: on several threads, each file's head is read once, and its rest only when the file is longer than the head. `kinds.rs` holds the kinds, in the order of design §3.5d: `headers`, `readmes`, `length`, `one-liners`, `thin`, `cites` and `ids`. Each is one function over the context. `thin` is a pointer: it is listed with its header share, but the scope line, `nothing to fix` and the JSON `findings` leave it out (design §3.5d, R30).

Choices where design §3.5d is silent: a path outside the root names nothing, since check reads only the root it runs in; a doc label or bare id is not a path, so it names nothing either; the `headers` kind asks the file system for each candidate's length, and only that, so an empty file is not a finding; a folder that the walk could not list is not judged for a README; a `readmes` folder is judged by the walked files under it, whatever the scope, so a folder of data alone (no file with a comment family in its subtree) needs none (R29); an `ids` finding is in scope when any of its docs is; an `ids` detail names each file once, joined by ` · `; `thin` sorts by header lines over total lines, compared as exact fractions, then by path; a file without a header is not `thin`, even at 80 lines or more; the JSON `kinds` list keeps `thin` with its items (a ruling: design §3.6 says `kinds` holds the kinds with findings, while §3.5d takes `thin` out only of `findings`).
