# show

The parts of `memex show` (design §3.3) are split from `../show.rs`, which runs the verb. It resolves the refs, reports the sections and misses, and sets the exit status. `section.rs` builds what one resolved target prints: a folder's section (its README or `(no README)`, its children, its citations and its chain), a file's (its header, or its whole text for Markdown, and its chain) or a doc's (its text and its fields, with no chain). A folder or file that cannot be read or listed is an io error for its own ref (SHOW-IO-01, SHOW-IO-02), which `../show.rs` reports as a miss. `show` resolves every ref before it builds a section, and `section::index_for` gives all the sections one citation index (`cite::Index::for_show`, design §2.3), built by one scan of every doc's tokens that resolves only those that can name one of the refs' targets. So a `show` of many refs scans once and builds no index of every citation; an entry of another root is given no index at all. A file's manifest label is read from the doc paths alone.
