# init

The init code, the modules of `memex init` (design §3.5b), split by what each one writes. `../init.rs` picks the target folder (the git toplevel, else the cwd), runs the steps in the order of design §3.5b, and prints the atlas of the target. `files.rs` writes `.memex/` (its `.gitignore`, `config.json` and `collections/.gitkeep`, each created or kept), and holds the helpers the other modules share: the listing that matches a special name exactly, the labels that print a path root-relative, the temp-file writes, the symlink check and the I/O error that names the kind and the path. `agents.rs` writes the AGENTS.md block between the markers (created, appended, replaced, kept, or left alone when the markers are damaged, a fence is never closed, or the file is a symlink) and appends the CLAUDE.md import once; it never creates CLAUDE.md. The markers and the import count only outside fenced code blocks, which `../../fence.rs` finds (design §2.3). `install.rs` copies the running binary to `$HOME/.local/bin` (or `%LOCALAPPDATA%\Programs\memex` on Windows) when no memex is on PATH, replaces it only when its bytes differ, and prints the PATH hint when its folder is not on PATH.

- `files.rs`: `store` (the `.memex/` files), `place`, `lists` (exact names from a listing, never `exists()`), `create_new` (a noclobber persist), `replace` (a persist that refuses a symlink and a read-only file), `is_link` (the entry itself, not followed), `read_text` (refuses a file that is not UTF-8), `write_temp` (a new file's mode, or the one it is given), `label`, `io_error`.
- `agents.rs`: `agents_md`, `claude_md`, `link_kept`, and the pure `merge`, which decides between Same, Changed and Refused from the text alone; `imports` and `ends_in_fence` read the CLAUDE.md text the same way. The snippet is `include_str!` of `assets/agents-snippet.md`, the one source.
- `install.rs`: `run`, `install` (created, kept or updated), `env_dir` (an absolute `$HOME` or `%LOCALAPPDATA%`), `memex_on_path` and `memex_in` (a listed program that can run, found on PATH outside npx's shim folders), `npx_shim` (a `node_modules` folder directly followed by `.bin`), `holds_program` (`memex` on unix, `memex.exe` or `memex.cmd` on Windows) and `on_path` (the install folder against PATH). Each platform difference has both arms.

Choices where design §3.5b is silent:

- The report names files, not folders: `.memex/` is implied by its files. A `.memex/` entry that is listed is kept whatever its kind. AGENTS.md and CLAUDE.md are read first, so a folder under one of those names is an I/O error (exit 3). A symlink under one of those names is warned about and kept, never written through (INIT-LINK-01, INIT-LINK-02).
- A damaged AGENTS.md is reported `kept`, with the warning on stderr, since nothing changed. So is a symlink. So is an AGENTS.md or CLAUDE.md whose last fence is never closed: a block or an import appended there would land inside that fence, and the next run would append another, so init leaves the file and warns (INIT-FENCE-05, INIT-FENCE-06).
- A block is written with the file's own line ending, CRLF when the file has one; the snippet itself is LF.
- AGENTS.md that is not UTF-8 is not rewritten: init exits 3 and names the file.
- CLAUDE.md that is the same file as AGENTS.md (a symlink) is kept, so the import never lands in AGENTS.md.
- A missing `$HOME` (unix) or `%LOCALAPPDATA%` (Windows) is an environment error, exit 3, because the binary has nowhere to go.
- On Windows `memex.exe` and `memex.cmd` count as installed. cmd and PowerShell run a PATH file only by a PATHEXT extension, so a bare `memex` (an npm shim for sh) is not a memex there. The conformance harness scrubs only `memex.exe` from PATH on Windows (`tests/harness/env.rs`), so a `memex.cmd` on a Windows runner would not be scrubbed from its cases.
- A PATH folder whose path has `node_modules` directly followed by `.bin` is npx's temporary shim, so a memex in it is not an install and init installs its own copy (INIT-PATH-03, and a unit test for the scan).
- An empty or relative `$HOME` or `%LOCALAPPDATA%` is the same error as a missing one, so the binary never lands under the cwd (INIT-INSTALL-04).
- A replaced binary that cannot be replaced, as on Windows while it runs, is left whole: init exits 3, and the error says it may be running.
- Written files get the mode of any new file (0o644 less the umask on unix), a replaced file keeps its own mode, and a read-only AGENTS.md or CLAUDE.md is refused (exit 3), never replaced. The binary is 0o755 on unix.
- An empty AGENTS.md gets the block alone, with no blank line above it.
- The atlas is `info::text_in` of the target, so the process cwd never changes. It ignores `$MEMEX_AGENT`: init has no `--agent`, and an invalid value must not exit 2 after the files are written (INIT-INFO-03).
- The `.gitignore` bytes are written here, as `logs/write.rs` writes them there; the two copies are the same design §4.1 text.
