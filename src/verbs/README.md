# verbs

The verbs are the commands that do work, one module each, with `here.rs` loading what the reading verbs share: the canonical cwd, the log store, and the corpus of its root, read while git finds the store. `log.rs` runs `memex log` (design §3.4): it checks the stream name, reads the body, places the entry and returns the ref, or the path as JSON with `--json`. `show.rs` runs `memex show` (design §3.3): it loads the corpus for the cwd's root, resolves each ref, builds its section and reports the sections and misses, with exit 1 when a ref failed. `search.rs` runs `memex search` (design §3.2): it takes the first doc of each label from the corpus, groups them (every log stream is the one `logs` group), narrows each group by its filters, then ranks it with `index/` when there are words, lists it when there are only filters, or prints its roster when `--in` names it with no words, where each line ends in the `<-N` count of direct citations. `lib.rs` dispatches to them; the other verbs are not built yet and still print their not-implemented line.

Choices where design §3.2 is silent: a hit's `snippet` in JSON is its one-liner in full, and the text cuts it at 120 characters; a log's age comes from the stamp that starts its file name, which is the instant of its `time`, so a log whose name has no stamp shows no age; the text shows `(showing N of M)` without the `--limit` hint; the fuzzy marker follows two spaces after the one-liner, as the design sample does; `--in` names only groups, so a stream name or an unknown name selects no group; a roster's default limit is 50, a listing's is 5 per group, and a search that gives neither words, filters nor `--in` prints nothing; the filters are read against the fields of the groups searched, so `stream:impl` is a filter over all docs but words over `--in readmes`.
