# verbs

The verbs are the commands that do work, one module each. `log.rs` runs `memex log` (design §3.4): it checks the stream name, reads the body, places the entry and returns the ref, or the path as JSON with `--json`. `show.rs` runs `memex show` (design §3.3): it loads the corpus for the cwd's root, resolves each ref, builds its section and reports the sections and misses, with exit 1 when a ref failed. `search.rs` runs `memex search` (design §3.2): it gathers the intent layer's docs and the log store's, finds each doc through the readers that load it, groups them, ranks each group with `index/`, and limits each group. `lib.rs` dispatches to them; the other verbs are not built yet and still print their not-implemented line.

Choices where design §3.2 is silent: a hit's `snippet` in JSON is its one-liner in full, and the text cuts it at 120 characters; a log's age comes from the stamp that starts its file name, which is the instant of its `time`, so a log whose name has no stamp shows no age; the text shows `(showing N of M)` without the `--limit` hint; the fuzzy marker follows two spaces after the one-liner, as the design sample does; `--in` names only groups, so a stream name or an unknown name selects no group; a search with `--in` and no words is the roster, which is not built yet, so it exits 2 with the not-implemented line. `corpus.rs` keeps no list of its docs, so `search` finds each doc's label with the readers that load it (the walk, CASES.md, manifests and the log store) and takes the doc from the corpus; a `Corpus` iterator would replace that gather step.
