# verbs

The verbs are the commands that do work, one module each, with `here.rs` loading what the reading verbs share: the canonical cwd, the log store, and the corpus of its root, read while git finds the store. `log.rs` runs `memex log` (design §3.4): it checks the stream name, reads the body, places the entry and returns the ref, or the path as JSON with `--json`. `show.rs` runs `memex show` (design §3.3): it loads the corpus for the cwd's root, resolves each ref, builds its section and reports the sections and misses, with exit 1 when a ref failed. `search.rs` runs `memex search` (design §3.2): it takes the first doc of each label from the corpus, groups them (every log stream is the one `logs` group), ranks each group with `index/`, and limits each group. `info.rs` runs `memex info` (design §3.5 and §3.6): it reads the atlas of the cwd's root, with the built-in counts, the manifest collections and their doc counts, the log streams and their new entries, the `to` count of the agent, and the `here` line, then prints it as text or as JSON; each duplicate case id is warned on stderr. `init.rs` runs `memex init` (design §3.5b): it picks the target folder, writes `.memex/` and the AGENTS.md block and the CLAUDE.md import, installs the binary when no memex is on PATH, then prints the atlas of the target; `init/` holds those steps, and its README.md says which module writes what. `lib.rs` dispatches to them.

Choices where design §3.5b is silent are listed in `init/README.md`.

Choices where design §3.5 is silent: a count of one is singular; the `to` line appears only when the agent has at least one entry; a stream's new entries are those no more than 24 hours old, inclusive; streams are ordered by their newest entry and then by name; the collections are alphabetical; `info` reads each manifest's docs itself, for the counts and for the warnings the JSON lists; an agent id that `log` refuses is a usage error for `info` too; a built-in collection has a `null` kind in JSON.

Choices where design §3.2 is silent: a hit's `snippet` in JSON is its one-liner in full, and the text cuts it at 120 characters; a log's age comes from the stamp that starts its file name, which is the instant of its `time`, so a log whose name has no stamp shows no age; the text shows `(showing N of M)` without the `--limit` hint; the fuzzy marker follows two spaces after the one-liner, as the design sample does; `--in` names only groups, so a stream name or an unknown name selects no group; a roster's default limit is 50, a listing's is 5 per group, and a search that gives neither words, filters nor `--in` prints nothing; the filters are read against the fields of the groups searched, so `stream:impl` is a filter over all docs but words over `--in readmes`.
