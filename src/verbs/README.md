# verbs

The verbs are the commands that do work, one module each. `here.rs` loads what the reading verbs share: the canonical cwd (or the folder `init` names in its place), the log store, and the corpus of its root, read while git finds the store and never freed, since the process exits after the verb. `log.rs` runs `memex log` (design §3.4): it checks the stream name, reads the body, places the entry and returns the ref, or the path as JSON with `--json`. `show.rs` runs `memex show` (design §3.3): it loads the corpus for the cwd's root, resolves each ref, takes its section from `show/`, and reports the sections and misses, with exit 1 when a ref failed; `show/section.rs` builds each section, and a folder that the walk could not list is that ref's io error. `search.rs` runs `memex search` (design §3.2): it takes the first doc of each label from the corpus, groups them (every log stream is the one `logs` group), ranks each group with `index/`, and limits each group. A search with no hits prints its hint on stderr, and stdout stays empty, or holds the document with no groups under `--json` (design §3.2 Zero hits). `search/` holds `listing.rs`, which builds each listing and roster group that `search.rs` returns. `info.rs` runs `memex info` (design §3.5 and §3.6): it reads the atlas of the cwd's root, with the graph's counts, the collections and their doc counts, the log streams and their new entries, the `to` count of the agent, and the `here` line, then prints it as text or as JSON; each duplicate id is warned on stderr. `info::text_in` gives `init` the agentless text atlas of a given folder. `check.rs` runs `memex check` (design §3.5d): it resolves the paths and globs to the scope they name, finds each kind's findings over it, and prints the report; a path that names nothing is its error, and the exit is 1. `check/` holds `scope.rs`, which resolves the scope and walks the corpus's entries, and `kinds.rs`, which holds the kinds in the order of design §3.5d; its README.md lists the choices where that section is silent. `init.rs` runs `memex init` (design §3.5b): it picks the target folder, writes `.memex/` and the AGENTS.md block and the CLAUDE.md import, installs the binary when no memex is on PATH, then prints the atlas of the target; `init/` holds those steps, and its README.md says which module writes what. `lib.rs` dispatches to them.

Choices where design §3.5b is silent are listed in `init/README.md`.

Choices where design §3.5 is silent: a count of one is singular; the `to` line appears only when the agent has at least one entry; a stream's new entries are those no more than 24 hours old, inclusive; streams are ordered by their newest entry and then by name; the collections are alphabetical; `info` takes each manifest's doc count and warnings from the corpus, which read them once; an agent id that `log` refuses is a usage error for `info` too; a built-in collection has a `null` kind in JSON.

Choices where design §3.2 is silent: a hit's `snippet` in JSON is its one-liner in full, and the text cuts it at 120 characters; a log's age comes from the stamp that starts its file name, which is the instant of its `time`, so a log whose name has no stamp shows no age; the text shows `(showing N of M)` without the `--limit` hint; the fuzzy marker follows two spaces after the one-liner, as the design sample does; `--in` names only groups, so a stream name or an unknown name selects no group; a roster's default limit is 50, a listing's is 5 per group, and a search that gives neither words, filters nor `--in` prints nothing; the filters are read against the fields of the groups searched, so `stream:impl` is a filter over all docs but words over `--in readmes`.
