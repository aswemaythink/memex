# collections

The collections of design §4.2. A manifest describes one folder of docs that memex does not write itself, and its kind says how the files are read: `folder` or `json`. A Markdown file needs no manifest; a `memex:` frontmatter key makes it a doc, and that reader lives in `intent/`. In a README the same key marks the README's folder as a root of the manifest it names instead. `frontmatter.rs` is the flat-YAML reader shared by logs, manifests and those docs, and `after_frontmatter` cuts a closed block from a text. `manifest.rs` loads and validates the manifests in `.memex/collections/` and dispatches to the reader of each kind, `folder.rs` or `json.rs`, over the roots that `roots.rs` keeps inside the repo root; `roots.rs` also parses the optional `roots` key. `marks.rs` joins each manifest's `roots` with the folders whose README names it in a `memex:` key (design §4.2 Roots), which the corpus collects as it walks, so finding them reads nothing extra, and it warns about a README that names no manifest. `title.rs` gives every kind its one-liner by one rule. `globs.rs` matches a manifest's files against its globs: the `include` of a json manifest and the `merge` of a folder one. `json.rs` also holds the scalar reader and the field and doc helpers that `folder.rs` shares with it. `testing.rs` holds the test-only helpers that the readers' tests share: a temporary tree, a manifest of a kind and doc labels.
