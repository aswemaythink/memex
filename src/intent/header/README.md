# header

The parts of the header reader (design §2.1). `families.rs` is the table of comment families: the markers each extension and file name uses, and the pragma lines that are skipped before a header. `scan.rs` walks a file's first lines past its blank, pragma and license lines, then reads the header block or a module docstring into text, and says whether that block runs to the last line. The entry point, `../header.rs`, decodes the bytes with the shared reader in `../../text.rs` (which drops a byte order mark), skips binary files and hands the lines to the scanner. When the block is still open and the file is longer than the 8 KiB read, it ends the text with a blank line and `… (header cut at 8 KiB)`, which only `show` prints: the index drops it (`without_note`), and a one-liner never reaches it. `lines.rs` counts a file's lines for `check` (design §3.5d): `header::with_lines` gives a `Head` from the same scan that finds the header, with the head's size, its line tally and the lines of its header and license blocks; the corpus keeps it only when `check` loads, and `Head::counts` reads past the head only for a file longer than it. `stream.rs` holds the line tally (`Tally`), with the byte order mark rule and the chunked read of the rest, for `lines.rs` alone.
