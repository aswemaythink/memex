# logs

The log store code. Four modules check a `memex log` entry before anything is written: `body.rs` reads stdin, drops a leading BOM, and refuses a terminal, an empty body, a body over 16 KiB, or one with no title; `front.rs` splits the agent's own leading `---` block off the body and refuses memex's keys and repeats inside it; `stream.rs` checks the stream name, its grammar, the reserved built-in and Windows device names and any manifest that already owns the name; `values.rs` checks the values of `--to`, `--tag` and the agent id and drops repeats from the lists. Then `write.rs` puts one entry in the store: memex's frontmatter with the agent's lines merged in, the body verbatim, a file name from the title's slug, and never an overwrite. `prune.rs` then deletes the entries that keep_logs has expired, by their filename stamp, and removes the stream folders its deletions empty; `cap.rs` then deletes the oldest entries until the store is at or under max_logs_mb. The rules are design §3.4 and §4.3; where the store is comes from `root.rs`.

- `body.rs`: `read_stdin` and `read` (the terminal refusal is injected so a unit test can pin it), `check_title`, the 16 KiB limit, counted on the raw bytes before CRLF becomes LF, and the leading BOM, dropped after that count.
- `front.rs`: `split` returns the agent block's lines and the body after its closing fence. A key is a column-0 identifier followed by a colon; every other line is kept as continuation.
- `stream.rs`: `check_grammar`, `check_reserved` and `check_collections`. `check_reserved` refuses the built-in names and the Windows device names. `check_collections` lists `.memex/collections/` under the nearest `.memex/` above the cwd, no higher than the git toplevel (found by `root::nearest_memex`) and under the store owner's `.memex/`, and refuses a stream whose `<stream>.json` is listed there by exact name; a missing folder lists nothing.
- `values.rs`: `list` for the comma lists, `agent` for `--agent` or `$MEMEX_AGENT` (only the one in use is checked), and `env_agent` for the variable alone, where an empty value is unset. Each value matches `[A-Za-z0-9._@/+-]{1,64}`.
- `write.rs`: the entry, its frontmatter in fixed key order, the title and slug rules, the `-2`, `-3` suffixes for a taken name (a name is taken when the persist fails and something exists there in any form), and the refusal of a symlinked stream folder. A stream folder that a concurrent prune removes is made again: `make_folder` makes it again after an AlreadyExists or NotFound from its create or a NotFound from the check after it, and `retry_vanished` tries `atomic::persist_new` again when its create fails while the folder is not listed under the store or says NotFound. Each loop makes at most `ATTEMPTS` (64) tries (design §4.3 Vanished entries).
- `prune.rs`: `run(store, keep, cap, now, written)`, called after every write whenever config.rs sets either limit. Its age pass lists each stream once and deletes the entries that keep_logs has expired; the entries it leaves go to `cap.rs`. It deletes only regular files named `YYYYMMDD-HHMMSS-*.md` one folder below the store, follows the store when it is a symlink but no symlink below it, and reports a failure as a warning on stderr, except NotFound: a path that a concurrent prune already removed is skipped silently (`warn`, design §4.3 Vanished entries). A stream folder that a writer has put a file into since the check is kept silently (`settle_removal`, design §4.3 Vanished entries).
- `cap.rs`: `prune_to(entries, cap, written)`, the size pass (design §4.3 Size cap). It stats each entry once, in parallel with `par::map`, and counts only regular files by length (`symlink_metadata`, so a symlink counts for nothing). If the total is over the cap, it sorts by entry name, then stream name, in byte order (oldest first), and deletes until the total is at or under the cap. The written entry is passed over but its bytes count; a refused delete warns and its bytes stay; a path that is gone subtracts silently. Each stream folder a delete emptied is then removed by `remove_if_empty`.
- `read.rs`: `load(store)` reads the entries as docs for `show`: every non-dot `.md` file one folder below the store, labelled `stream:id`, with its frontmatter as fields and its first title line. A missing store has none, and an entry or folder that is gone (NotFound) is skipped without a warning (`entry_doc` and `note`, design §4.3 Vanished entries).
