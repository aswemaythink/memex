# index

`index/` is the search index that `memex search` builds in memory. It is built for each group of docs on each run and writes nothing to disk (design §3.2). `mod.rs` builds it from each doc's id, title and body, counting the docs in runs on several threads, and ranks a query with BM25F, finding each query word's candidates by one scan of the runs' distinct terms; `vocab.rs` holds each run's terms with their postings in doc order, and the runs are never joined into one vocabulary; `tokenize.rs` splits text into the lowercase words and the whole ids and paths that both the docs and the query use; `bm25.rs` holds the constants and the arithmetic of BM25F; `fuzzy.rs` tells whether two words are one edit apart; `filter.rs` reads a term as a `field:value` filter or a `since:` bound, and matches docs against it before any ranking (design §3.2); `hold.rs` says which docs hold a `+` or `!` word, for the hits that those words cut (design §3.2 Operators).

- `filter.rs`: `classify` reads one term, once the verb has taken off its `+` or `!` operator, as a filter when it reads `name:value` and either `name` is reserved (`agent`, `to`, `tag`, `branch`, `worktree`, `since`) or some doc in the groups searched holds that field; any other term is words. A `!` filter keeps the docs that the same filter drops, docs without the field or the time among them. A reserved name with no value (`tag:`) is a usage error, not a word. A filter matches exact text or an item of a list, ignoring ASCII case. `since:` takes `Nm`, `Nh`, `Nd` or `Nw` (the duration grammar of design §4.3), or `YYYY-MM-DD` as UTC midnight, and keeps the docs whose `time` is at or after the cutoff; a bad value is a usage error. `check_in` checks the `--in` names before a search: a built-in name (`readmes`, `headers` or `logs`), a collection or stream that a doc holds, or a manifest that loads (only then is the manifest file read), else a usage error.
- `mod.rs`: `Index::build` counts each run of docs on the threads and keeps the runs as they are, with the norms of every doc's fields. `Index::search` finds each query word's candidates in one scan of every run's distinct terms, on the threads: its stem-mates, the prefixes of a plain word of 3 or more characters, the one-edit variants of a plain word of 5 or more characters, a whole id or path by its exact term, and the longer whole ids and paths that it begins at `-`, `/` or `.`. Only those terms' postings are read, run by run in doc order, so a doc's sums are taken in the same order as before. A query word matches a doc at its best tier only: an exact or stem match (multiplier 1.0), else a prefix (0.5), else a one-edit variant (0.3). Hits are ranked by score rounded to 1e-9, then by label. The runs are never freed, since a search ends with the process (perf P-IDX).
- `hold.rs`: `passing` tells which docs pass a query's `+` words (each must be held) and its `!` words (none may be held). A doc holds a word at tier 0 only: the exact word or a stem-mate, or for an id or path the whole token or a longer one it begins at `-`, `/` or `.`; a prefix or a one-edit match never holds. One scan of the runs serves every operator word, and the scores are neither read nor changed, so `search` ranks a `+` word as a bare one does and drops the hits that fail the operators afterwards (design §3.2 Operators).
- `tokenize.rs`: `for_each_token` hands a doc's tokens to a callback, and `query_tokens` gives a query term's. A run of letters, digits, dashes, dots and slashes that is an id or a path (it holds a dash or a slash, or a dot before a letter) is one whole token, lowercased, and the document also gets its words. A word is a run of Unicode letters and digits (`char::is_alphanumeric`), lowercased by `str::to_lowercase`; `fuzzy.rs` and the prefix gate count characters, not bytes. A query's whole token matches that whole token and the longer whole tokens it begins at `-`, `/` or `.`, so `NAME-001` does not match `NAME-002`, and `NAME-1` does not match `NAME-10`. A doc's tokens are borrowed from its text, with one reused buffer for a capital, so indexing allocates per distinct term, not per token.
- `bm25.rs`: the constants k1 1.2, b 0.75 and the default field weights id 4, title 3 and body 1, with the length normaliser of each field, the idf `ln(1 + (N - n + 0.5) / (n + 0.5))` and the saturation `s / (k1 + s)`. A manifest's `weights` replace the defaults of its own group (`field_weights`, design §4.2), and `mod.rs` ranks each group with the weights it is given.
- `fuzzy.rs`: `one_edit` tells whether two words differ by one insertion, deletion or substitution.

Choices where design §3.2 is silent: the idf is the BM25 form over the group's own docs, so every group is ranked alone; a match multiplier scales a term's weighted frequency before it saturates; a query word takes the best tier that a doc has for it, so a prefix or a one-edit term counts only where no exact or stem match exists; a field's normaliser uses the mean length of that field over the group. Scores are compared rounded to 1e-9, and the ties then go by label.
